Hello October!

September was the month decision models took over. ChatGPT co‑founder Diogo Almeida [released a model](https://typesafe.ai/blog/introducing-system-one-models-and-jev) with a new architecture. Instead of walls of text, the model could only answer with decisions or choices. You could consider this a restriction than a new feature, but so is Twitter

Caught up in the storm, everyone and their mother has released their own Jev, to list a few: Cloudflare Clef, Perplexity Decisions, OpenAI Decisions, Amazon Strands Decider, Liquid D1, Together Tev1x, Mercury Decide and others who I'm skipping for brevity.

Shopify argues that, in the age of AI, creating two apps that translate code between codebases is not a big deal. Therefore, you might as well use native apps rather than React Native. They claim native apps can deliver better performance and UI/UX than React Native apps. Shopify also maintains many important React Native libraries. It has [renewed its commitment](https://x.com/mustafa01ali/status/2099476652300419450) to them, indicating ongoing sponsorship and transferring ownership to open source.

## Tutorials

### [How we made claude.ai 3x faster in two weeks - claude.dev](https://claude.dev/blog/how-we-made-claude-ai-faster/)

Claude's desktop app is now 3× faster. The blog not only describes the improvements that increased speed, but also explains how they created a benchmark to verify performance, enabling the model and harness to measure it automatically.

Read alongside: [Automating eval design and hillclimbing with Claude](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)

### [Wrong, not broken - AWS](https://aws.amazon.com/blogs/aws-insights/wrong-not-broken/)

It's not every month that I feature an AWS blog post here. There are situtations where you see your thoughts expressed so well in words and this is one of them. Before Agents, we had code that worked mostly deterministically - if something did not work, it was broken - it was at least broken on one device one network in someone's basement. But if agents are creating interfaces that your user interacts with, there are surely cases where the interface is wrong, but not broken.

### [How Notion handles concurrent editing with CRDTs](https://www.notion.com/blog/how-notion-handles-concurrent-editing-with-crdts)

Notion must be the among the people using CRDTs for conflict management at scale after Google and Microsoft. If you need multiple people editing the same document at the same time and preserve some semblance of reality in the final edits - this is the article to read.

### [How to scale intent, quality, and artistry with Al | Katie Dill (Stripe)](https://youtu.be/GLvFTMtw4Jk?si=g83UqY7TRUCQfl5Y) - YouTube

Katie Dill, design leader at Stripe, names UI slop as the UI slop problem. She compares it to post war housing boom where every building was forced to look the same despite serving different purposes. She sets up these principles to build software with "soul":

- Define a clear point of view
- Encode standards into system
- Refuse to confuse done with good
- Instead of using AI only for speed, leverage it as a catalyst for experimentation

### [Detect when elements overlap with CSS - Ahmad Shadeed](https://ishadeed.com/article/css-detect-overlap/)

Ahmad Shadeed uses a smart scroll animation technique to find if elements are overlaps just using CSS.

### [How Turbopack chunks your JavaScript - Next.js](https://nextjs.org/blog/turbopack-chunking)

The bundler faces a Goldilocks problem: keeping reused chunks on every page duplicates code and inflates file sizes, while optimizing too many chunks into separate files creates excessive network requests. The blog explores how Turbopack solves this issue.

### [The best dark mode toggle is probably none - Lea Verou](https://lea.verou.me/blog/2026/dark-mode-toggles-2/)

I didn't expect so much discussion about how many toggles a theme selector should have, but here we are. Have you made up your mind? How many options should be given to the user for toggling dark mode?
