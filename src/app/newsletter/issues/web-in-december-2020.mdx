React Team went on their vacations for this year leaving us scratching our heads. A new RFC is now out: [Zero-Bundle-Size React Server Components](https://reactjs.org/blog/2020/12/21/data-fetching-with-react-server-components.html). This time, instead of random keywords, the team decided to put out a full hour Youtube video explaining the concept.

- React can render components on the server and send the resulting HTML via network
- The components on the server can access NodeJS elements and interoperate with languages that NodeJS can.
- It doesn't involve hydration and HTML is served to the client in a special data format that React library on the frontend can unpack - libraries like Ember have explored this pattern before.

Just hours after this left everyone head scratching and deep into PHP memes, Basecamp came out with another library that tasted like satire. [Turbo](https://github.com/hotwired/turbo) is extracted from the magic that powers _Hey!_ that we had talked about in previous newsletters. Turbo gives you the power of Single Page Applications while writing less JavaScript.

# In the Spotlight 🔦

There has been some really great CSS-in-JS frameworks coming out. With these libraries, we can:

- custom CSS as CSS inline - no style objects
- build in conditionals
- grouping common styles
- no @ apply in CSS - create components
- no more enabling/disabling styles

[Here's a more detail explainer on my blog.](https://blog.agney.dev/new-styling-favorite/)

Highlighting some of my favorites:

- [twin.macro](https://github.com/ben-rogerson/twin.macro) is a babel macro that transforms tailwind classes into your favourite CSS-in-JS library. This means zero run time.
- [twind](https://github.com/tw-in-js/twind) has CSS-in-JS build-in and with benchmarks faster than any other solution in \~11kB.
